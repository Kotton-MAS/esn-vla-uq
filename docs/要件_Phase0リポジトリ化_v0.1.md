# 要件: Phase 0 リポジトリ化 v0.1 — ESN による VLA 不確実性定量化

リポジトリ名: `esn-vla-uq`

> この文書は公開版です。実装の指針となる技術要件のみを収録しています。

______________________________________________________________________

## 目的（なぜ作るか・何が解決されるか）

- Phase 0（最小実証: LIBERO × デジタル ESN read-out × prediction interval）を公開リポジトリとして実装する
- VLA の不確実性定量化は 2025–2026 に活発な研究領域（SAFE, FAIL-Detect, VFD, ACE, STAC 等）である。本手法は
  **閉形式・アンサンブル不要・物理リザバーへ移植可能**という 3 条件を同時に満たす点で既存手法と異なる
- ソフト ESN → エッジ → 物理リザバーという長期ロードマップの第一里塚

## スコープ

### やること（v0.1）

- openpi（π0）の LIBERO 評価ロールアウトからのデータ収集パイプライン
- デジタル ESN read-out による不確実性スコア＋予測区間の算出（conformal prediction ベース）
- 較正評価: reliability diagram / ECE をコマンド一発で出力
- **リザバー診断モジュール**（本リポジトリの中核）: スペクトル半径・ESP 検証・メモリ容量等の指標をレポート出力
- README: 3 行クイックスタート＋デモ GIF ＋手法の 1 段落説明
- テスト（pytest）と lint、最小限の CI

### やらないこと（スコープ外を明示）

- 物理リザバー・メモリスタ実装（Phase 1 以降）
- 四足歩行・ロコモーションへの横展開（v0.2 以降）
- π0 以外の VLA（SmolVLA, GR00T 等）対応。ただし将来対応を見越しデータ収集層は抽象化しておく
- リアルタイム介入（不確実性による実行停止・リカバリ）— 検知のみ、介入はしない
- ハイパーパラメータの網羅的探索。v0.1 は「動いて較正が見える」ことが目的

## 入力 / 出力

- **入力**: openpi の LIBERO 評価ロールアウトから収集する
  **action chunk 系列＋固有受容感覚（関節状態・グリッパ状態）の時系列**、およびエピソード成否ラベル
  - 採用理由: (a) policy server の API 境界で取得でき、π0 内部改造が不要＝疎結合設計と整合
    (b) 時間構造を持つ信号であり ESN の時系列処理と本質的に相性が良い
    (c) 低次元信号のため将来の物理リザバー移植（crossbar 注入）に直結
  - VLM 特徴の注入は bottleneck 設計が絡むため **v0.2 以降に延期**。ただしデータ収集層は特徴追加を見越して抽象化しておく
- **出力**:
  - エピソード／ステップ単位の不確実性スコアと予測区間（CSV / JSON）
  - 較正レポート（reliability diagram PNG、ECE 値）
  - リザバー診断レポート（スペクトル半径、ESP、メモリ容量）
  - デモ GIF（LIBERO タスク映像＋不確実性バーのオーバーレイ）

## 制約

- **技術的制約**:
  - 環境: Ubuntu 24.04 / コンシューマ GPU 1 枚（VRAM 16GB 級）/ Python 3.12+
  - プロジェクト雛形: Copier 製 `uv-template` から生成、uv でパッケージ管理
  - ESN は自前実装（NumPy）。理由: ESP・メモリ容量等の診断を組み込むため。
    ReservoirPy は比較検証用の参照実装として将来 dev 依存に置く
  - openpi は依存に含めず「ロールアウトログを食う」疎結合設計（openpi 側の破壊的変更から絶縁する）
- **非機能要件**:
  - LIBERO 1 タスクスイート分の ESN 学習・評価がローカル GPU 1 枚で完結すること
  - 乱数シード固定で結果が再現可能であること
  - ログは標準の logging、図は matplotlib のみ（依存最小化）

## 受け入れ条件（「完成」の判定基準）

1. `uv sync && uv run demo` 相当のコマンド 3 つ以内で、同梱サンプルデータからデモが再現できる
2. 較正評価コマンドが reliability diagram（PNG）と ECE 値を出力する
3. リザバー診断コマンドがスペクトル半径・ESP 判定・メモリ容量を出力する
4. README 冒頭にデモ GIF があり、初見の読者が 10 秒で「何ができるか」わかる
5. pytest が全て green、CI（GitHub Actions）が main で通っている
6. LICENSE ファイルと引用情報（CITATION.cff）がある

### 設計要点

- π0 の推論構造: policy server + LIBERO 評価スクリプト。観測トークンをキャッシュし、
  flow matching 10 ステップ統合、16–25 action を実行後に再推論
- 核心論点: π0 は flow matching による確率的生成のため「信頼度」を素朴には出せない
  → ESN read-out の差し込み位置がこの問題への解
- 新規性ポジション: VLA 不確実性定量化は 2025–2026 に研究が活発。
  本手法の差別化は「閉形式・アンサンブル不要・物理移植可能」の 3 条件同時達成
- 評価軸: 成功率ではなく較正（reliability diagram / ECE）
