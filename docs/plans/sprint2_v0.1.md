# Sprint 2 仕様: conformal 予測区間と較正評価

Sprint 1（ESN コア・リザバー診断・合成データ）の上に、要件書の
「不確実性スコア＋予測区間」と「較正評価（reliability diagram / ECE）」を載せる。

## ゴール

```
uv run esn-vla-uq calibrate
```

で、同梱の合成データに対して予測区間・被覆率・ECE・失敗検知 AUROC が
再現可能に出力される。

### 1 の帰結（スコープの縮小）

要件書の Sprint 2 は「openpi ロールアウト収集スクリプト、conformal 区間、較正評価
コマンド」の 3 点だったが、**openpi 収集は本スプリントから外す**。実ログも仕様も
参照できない状態で `OpenpiLogSource` を書くと、フィールドのマッピングが推測になる。
推測で書いたマッピングは「動くが正しさを誰も確認していないコード」になり、実ログが

Sprint 1 で `data/sources/`・`data/invariants.py` の分離（A1・S7）を済ませてあるため、
`OpenpiLogSource` の追加は既存コードを触らずに済む。実ログが入手できた時点で
別スプリントとして切り出す。design.md 8 節の未解決論点 2 はそのまま残す。

### 2 の帰結（予測タスクの定義）

- 入力 `u[t] = [state[t], action[t]]`（`FeatureSet = "state_action"`、`D_u = 15`）
- 目標 `y[t] = action[t+1]`（`D_y = 7`）
- 各エピソードの最終ステップは目標が無いため落とす（`T_i - 1` 標本）
- エピソード境界を跨がない（3.9 節の方針。`run_episodes` を使う）

**なぜこの定義か**: 「観測できる情報から次の行動がどれだけ予測できるか」を測る。
ポリシーの挙動が不安定になる（＝失敗に向かう）区間では次の行動が予測しづらくなる、
という仮説を検証できる形にする。要件書のデモ GIF「失敗直前に不確実性バーが跳ねる」
とも直結する。

### 3 の帰結

明示的なメッセージ付きの `ImportError` にする。コア（ESN・診断・conformal・較正の

## 設計上の要点（実装前に決めたこと）

### 3 分割が要る

split conformal は較正集合が**学習に使われていない**ことを要求する。read-out の
学習集合と較正集合が重なると残差が楽観的になり、区間が過小になる。したがって
fit（read-out 学習）/ calibrate（分位点）/ test（評価）の 3 分割にする。

### 非適合度スコアを 2 種類実装する

design.md 8 節の未解決論点 3（生の絶対誤差か、分散で正規化した適応型か）に答える。

- `absolute`: `s = max_j |r_j|`
- `normalized`: `s = max_j |r_j| / (sigma_j(x) + beta)`。`sigma(x)` は
  リザバー状態から `log|r|` を予測する第 2 の ridge read-out で推定する
  （Papadopoulos らの normalized nonconformity）

**両方を実装するのは比較のためではなく、`absolute` では要件を満たせないことを
示すため。** `absolute` の区間幅は全ステップで一定になるので、被覆率は正しくても
「どのステップが危ないか」を区別しない（失敗検知 AUROC が 0.5 付近になるはず）。
要件書のデモ GIF が要求する「失敗直前に跳ねるバー」は `normalized` でしか作れない。
この対比を数値で出し、既定を `normalized` にする。

### 多次元目標の扱い

`action` は 7 次元。次元ごとに独立した区間を出すと被覆率は次元ごとの周辺被覆に
なり、「区間に入った」の意味が曖昧になる。スコアを次元方向の max でスカラー化し、
全次元が同時に区間内に入る確率として被覆率を定義する（同時被覆）。

### 較正評価の指標

回帰の予測区間に対する reliability diagram は、名目被覆率 `1-α` を横軸、経験被覆率を
縦軸に取る。ECE は両者の差の絶対値の平均とする（分類の ECE の直接の転用ではないため、
出力とドキュメントで定義を明記する）。

## 評価軸

- 被覆率が名目値の近傍に入る（有限標本の揺らぎを考慮した許容幅を明示する）
- `normalized` の失敗検知 AUROC が `absolute` を有意に上回る
- 同一 seed で 2 回実行した結果がタイムスタンプ以外一致する
